# 升级

## 应用内更新

1. 在“设置”中开启每日检查，或点击“检查更新”。Stable 渠道只接收正式版；想接收 Beta 预发布时选择 Beta。
2. 发现新版本后查看版本与更新说明，选择是否更新。选择稍后不会下载或替换程序。
3. 确认更新后，屏序下载自带运行时的 Windows x64 ZIP，校验文件完整性和版本。下载或校验失败时保持当前程序。
4. 下载完成后自动退出旧程序、替换程序组件并重新启动。更新过程中保留原有设置、组合、壁纸和其他运行数据。

新安装默认开启自动检查；升级会保留原有开关，不会重新启用用户已关闭的检查。成功检查最少间隔 24 小时，失败至少 1 小时后重试；手动检查不受此限制。

更新助手只替换 `App`、`Diagnostics` 和 `package-manifest.json`，不会删除整个安装目录。程序文件替换或新版启动失败时尝试恢复旧版；如果恢复遇到文件占用等问题，界面会报告原因和保留的恢复目录。不要在恢复问题解决前手动删除该目录。

## 手动升级

旧版本没有应用内更新功能、自动更新不可用，或需要完整刷新文档和安装脚本时，可以手动升级：

1. 从官方 Release 下载并校验 ZIP。
2. 从托盘退出屏序。
3. 将全新解压的发行包内容覆盖到原安装目录，包括 `App`、`Diagnostics`、说明文档和新版安装、升级、卸载脚本；不要先删除整个原目录。
4. 保留 `Config`、`Wallpapers`、`Cache`、`Thumbnails` 和 `Logs`。
5. 启动新版本，确认设置页显示正确数据目录和开机自启状态。

`upgrade.ps1` 使用同一安装脚本覆盖程序文件，不会删除运行数据。脚本安装只支持 `%LocalAppData%\Programs` 下的目标目录；可在新发行包目录运行 `./upgrade.ps1 -PackagePath .`。其他解压位置按上述步骤覆盖发行文件。手动脚本不会关闭正在运行的程序，使用前需自行从托盘退出。

## 配置兼容

程序不生成普通配置历史或壁纸删除备份。自动更新的临时旧程序文件只用于本次替换或启动失败的恢复，不提供跨版本数据回退。

1.2.0 会把旧特定组合迁移到 schema 6，并保留原有身份绑定。新通用组合包含旧版本不认识的字段，因此创建通用组合后不要让旧版本读写同一份配置；如需回退，请使用自行保存的升级前数据副本。
