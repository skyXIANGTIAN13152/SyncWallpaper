# 壁纸组合匹配

组合有两种匹配方式。特定组合保存物理显示器指纹、逻辑角色、壁纸和填充方式；通用组合只保存屏幕方向、位置编号、壁纸和填充方式。两者均可命名、停用和手动应用。

## 自动匹配

1. 优先检查已启用且壁纸配置完整的特定组合，按活动显示器数量筛选，再对角色与物理显示器做一对一分配。
2. 依照 EDID 序列号、设备路径、实例名和硬件拓扑分层评分。唯一且可靠的完整特定匹配始终优先于通用组合；不完整的高优先级特定组合不会挡住完整的特定组合。
3. 没有可安全自动应用的完整特定匹配时，筛选已启用、横屏数量和竖屏数量分别与当前整套完全一致的通用组合，再按 `Priority` 降序、`Id` 的 ordinal 升序选择第一套有可应用壁纸的组合。数量不符的高优先级组合不会挡住数量完全匹配的组合。
4. 通用组合至少有一个位置配置了壁纸才允许应用。空白组合、所有位置都未选壁纸、任一方向数量不同，都不算成功匹配；总屏数相同但横竖构成不同也不匹配。
5. 应用前仍检查实际图片和目标路径，应用后逐屏回读验证。特定组合身份歧义或弱证据不会被当成已确认身份；通用组合明确使用位置规则，身份置信度为 0，界面显示匹配方式。

## 特定组合与兼容候选规则

“显示兼容候选”用于在可靠身份不足时保留线索，帮助检查旧组合。开启后，弱证据或未知身份的配对也进入候选计算；关闭后只评估可靠身份配对。它会影响候选搜索，但不会降低应用壁纸的安全要求，也不影响通用组合的位置规则。

特定组合先要求已勾选“参与匹配”，保存的角色数和期望屏数均与当前活动屏数一致，再寻找一对一分配：每个角色只能对应一块屏幕，同一屏幕不能重复分配。关闭“参与匹配”后，自动匹配和手动“应用选中组合”都不会应用这套组合；需要先重新启用。通用组合停用后同样不能应用。

每个配对按以下层级取第一个成立的依据，不把各行分数累加；同来源的稳定 ID 相同也按其来源归入对应层级。

| 依据 | 证据等级 | 身份原始分 | 用于组合的单屏分／置信度 |
|---|---|---:|---:|
| 厂商、产品代码及可用 EDID 序列号一致 | 可靠身份 | 1200 | 1240／100% |
| 永久 monitorDevicePath 一致 | 可靠身份 | 900 | 940／94% |
| WMI InstanceName 一致 | 可靠身份 | 820 | 860／86% |
| 显卡适配器、Target ID、接口类型及接口实例一致 | 可靠身份 | 760 | 800／80% |
| 有效 Container ID 一致 | 兼容候选 | 600 | 640／64% |
| 厂商及产品型号、接口类型及接口实例、几何全部一致 | 兼容候选 | 520 | 560／56% |
| 厂商及产品型号、几何一致 | 兼容候选 | 360 | 400／40% |
| 仅几何一致 | 兼容候选 | 120 | 160／16% |

这里的“几何一致”要求当前宽度、高度、旋转值、桌面 X 坐标和 Y 坐标全部相同。刷新率、DPI、HDR、主屏状态不参与这一条件；仅型号相同不足以构成兼容候选。Container ID 必须是有效 GUID，并排除空值及无意义的占位值。Windows 临时显示编号和枚举顺序都不作为永久身份。

非零身份分在组合计算中统一加 40 分；单屏置信度为该分数除以 10 后取整数，最高 100%。组合总分用于比较候选，组合置信度取所有角色中最低的单屏置信度。因此，多加几块已确认的屏幕不会掩盖另一块屏幕的弱证据。可靠身份还需达到组合的最低置信度，默认 80%，编辑保存范围为 80–100%；兼容候选始终不允许直接应用。

若两边都有可用序列号，而厂商、产品及序列号组成的完整身份键不同，配对直接记为未知身份、0 分；相同路径或接口也不能覆盖这个冲突。开启兼容候选后，这类 0 分配对仍可能出现在多屏诊断映射中，但整套候选不能应用。路径、实例名、Container ID、分辨率或方向差异会记录为冲突信息，本身并非一律否决；仍可由更强身份依据确认。

同一组合存在多个最高分分配、同优先级组合得分相差不超过 20 分，或无可靠序列号的同型号多屏仍依赖弱证据时，会提示需要确认，不猜测屏幕。兼容候选既不会自动换壁纸，也不能通过“应用选中组合”绕过确认；请先在“显示器识别”中显示 A/B/C、确认物理屏幕并重新保存绑定。

如果没有完整、安全的特定匹配，而已有可应用的通用组合，自动流程会使用通用组合；不会为了显示兼容候选而阻止通用匹配。通用组合按用户明确设置的方向和位置工作，无须把弱身份线索当成可靠身份。

## 通用位置规则

- 当前宽度大于或等于高度为横屏，否则为竖屏；笔记本内置屏也参加编号。
- 横屏和竖屏分别按桌面 `X` 升序、再按 `Y` 升序编号，即从左到右、同列从上到下。位置完全相同时按 `MonitorDevicePath` 的 ordinal 顺序决定；Windows 枚举顺序不影响结果。
- 从 0 横屏、0 竖屏的空白组合开始添加「横屏1」「竖屏1」等位置，不设置屏幕数量上限。编号使用从 1 开始的正整数；方向与编号的组合必须唯一，每项保留独立绑定 ID。
- 每个方向的需求数量取已保存位置的最高编号，无该方向位置时为 0。例如只保留横屏1、横屏3，就要求当前完整连接 3 横屏、0 竖屏；横屏2是保留当前壁纸的位置，横屏3仍对应实际第三块横屏。
- 删除中间位置后保留其余编号；删除末尾位置会使需求数量随最高编号降低。新增时使用同方向最小的空缺编号，不会按最大编号预先生成大量空白位置。
- 当前横屏数、竖屏数必须分别等于组合的需求数量。例如当前 1 横屏、1 竖屏不会套用 2 横屏、0 竖屏的组合；多一块或少一块屏幕也不会部分套用。断开的屏幕不参与当前数量统计。
- 整套数量匹配后，未选择壁纸的位置和编号空缺位置保留当前壁纸，其余位置按顺序应用。配置中暂时没有接入的屏幕位置仍保留，但整套组合需等数量一致后才可应用。
- 通用组合不保存硬件身份，也不支持会改变 Windows 全局位置模式的 Span 跨屏填充。

手动“应用选中组合”可明确应用选中的通用组合，即使当前存在特定匹配，但仍须横屏、竖屏数量分别完全一致，不能绕过整套数量检查。随后发生自动检测时仍按特定组合优先的规则选择。手动应用不会提升组合优先级。

配置格式为 schema 6，旧组合迁移后保持特定匹配方式。空白或未配置壁纸的通用组合可以保存，稍后继续编辑。

通用匹配成功后，在内存中保存全体活动屏幕的布局快照，包含未选壁纸和编号空缺位置。应用前重新核对整套路径、方向及桌面位置；数量或布局已变化时拒绝旧匹配结果，应用中变化则停止并尝试恢复本次已写入屏幕。快照不写入通用组合的硬件身份字段。

## 拓扑变化

开机、插拔 HDMI/DP/USB-C、方向/布局变化、睡眠唤醒和 Explorer 恢复都会触发重新检测。拓扑稳定后立即匹配现有组合；匹配成功自动应用，无需用户再点“应用”。
